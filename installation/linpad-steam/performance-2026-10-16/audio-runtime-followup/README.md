# Actual game audio stream observation — physical game stream and bridge progress verified

The operator reported that build4449 progressed beyond FMOD startup with the baseline audio environment unchanged; earlier FMOD33/nosound failure lines disappeared. This is stronger startup evidence than the isolated helper test, but neither absent errors nor a connected Pulse context establishes audible playback.

`audio-stream4449-probe GAME_PID` performs two bounded, read-only native `pactl` queries five seconds apart against the existing `unix:/tmp/ishaudio/native` server. It prints the known ishaudio sink index and only stream state whose `application.process.id` matches the caller-supplied numeric game PID. It emits numeric index/sink/PID/latencies, corked/mute booleans, aggregate stream count and query exit code. It does not print names, arbitrary client properties, account information, credentials, or the game's environment. It creates no audio stream, changes no volume/cork state, and never opens the PCM FIFO. The stream parser has three synthetic matching/privacy fixtures.

The probe uses the already qualified private config and all-zero synthetic token, with isolated HOME/XDG_CONFIG_HOME. It does not read normal Pulse authentication-cookie locations. It downloads only that config/token and the pinned parser into the diagnostic directory, then posts the narrow output. Each sink query is bounded to6seconds, stream query8seconds, plus1second termination grace; three downloads can each take20seconds. A whole invocation can therefore legitimately exceed60seconds. Check each `QUERY_EXIT`, not only the final script exit, when qualifying results. A successful query with no PID match can mean no stream or absent process identity metadata; it is not proof of failed FMOD initialization.

The application's native bridge writes `tmp/ishaudio-stats.txt` in its iOS app container once per second. This is outside the guest `/tmp`. The parent operator may pull that fixed file twice around the stream observation; no FIFO read is required. Whitelisted counters are `frames_received`, `frames_played`, `frames_dropped`, `underruns`, `buffered_ms`, `target_ms`, and `playing`. `frames_received` advances when the bridge enqueues PCM frames; `frames_played` advances when its AVAudioSourceNode render callback consumes ring-buffer frames. These include silence and aggregate all guest streams. Pairing a matching game stream with advancing counters proves a plausible output path, not that the content is non-silent or audible on the device. Host mute, volume, hardware route and the user's listening experience are separate gates.

Implementation anchors: `app/Desktop/ISHAudioBridge.swift` lines96/115/181/210/369 and the official [PulseAudio17 pactl source](https://raw.githubusercontent.com/pulseaudio/pulseaudio/v17.0/src/utils/pactl.c).
