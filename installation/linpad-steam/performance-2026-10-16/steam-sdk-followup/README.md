# Official x86 Steam SDK companion preparation

The actual Hollow Knight log reports that SteamAPI could not locate a running Steam instance and could not load `/root/.steam/sdk64/steamclient.so`. These are separate conditions. The current direct diagnostic launch already exports SteamAppId/SteamGameId367520. The ARM64 `steam-local` launcher starts the client binary directly, bypassing the official bootstrap's SDK symlink setup. The previously repaired sdkarm64 launch-wrapper does not supply sdk64's x86 library.

Valve's exact ARM64 public-beta manifest version1792110651 includes `bins_sdk_linuxarm64`, a legacy companion bundle containing both linux32 and linux64 client libraries, alongside a separate ARM64 SDK bundle. The prepared linux64 client is verified ELF64 x86-64; the existing `steamrtarm64/steamclient.so` is AArch64 and cannot serve as the x86 game's library. The official bootstrap source creates `.steam/sdk64` pointing at Steam's linux64 directory. The selected versioned directory preserves that API path without replacing the ARM client.

The downloaded bundle matches the manifest SHA256c23f87048d79f2c05821e6ce203ff89816b350bf0211d864bd15b32bc20b321b. Its two linux64 members are steamclient.so51,017,392bytes and crashhandler.so1,002,544bytes. Their hashes, exact HTTPS URL, ELF build ID and dependencies are in PROVENANCE.json. The derived tar is18,199,806bytes, SHA256e9f627ea5bae77e2cc3cb704e561b85c84cc3df9376c7395ad07c8e08c17f524. These official binary inputs and payload remain local/served; they are not included in the source archive.

`install-steam-sdk-x86` downloads and checks the tar, validates both member hashes and x86 ELF identity, and stages the unchanged libraries under `/opt/steam-sdk-x86/1792110651/linux64`. It then runs the existing x86 loader via patched FEX with `--list` to resolve dependencies. A missing sdk64 link is created; a different symlink is moved to a timestamped backup first; an existing real file/directory is refused and preserved. An already installed matching version/link is reused. It does not launch Steam, read or write account/configuration data, alter the game, or replace any system library.

The exact local loader check passed in0.218s with all six dependencies resolved from `/opt/hollow-runtime`. This invokes the loader's listing mode, not the Steam library's constructors or entrypoint; it is dependency validation, not SteamAPI initialization. The installer performs the same check before changing sdk64. Installation and subsequent SteamAPI success are separate pending device gates at this checkpoint.

When the parent chooses to test integration, Steam must be running under the same guest user and the game's Steam launch context must be retained. The custom compatibility tool already preserves working directory and SteamAppId. Official [Steamworks initialization documentation](https://partner.steamgames.com/doc/sdk/api#initialization_and_shutdown) requires a live Steam client and valid app/user context. The ARM manifest shipping x86 libraries supports the expectation of an IPC route across CPU architectures, but this setup's actual IPC success remains unverified. Do not replace SDK libraries with emulators or bypass account/license checks.

Rollback only needs the new sdk64 symlink removed and any recorded `.linpad-backup-TIMESTAMP` link restored. The versioned payload can remain unused. The installer leaves its diagnostic download directory/report in `/tmp` for review; it never deletes an existing SDK directory.
