# Independent single-step invalidation review

Read-only review of the graphics agent's current `jit/jit.c` and `jit/jit_internal.h` patch after physical TimeProfiler identified ss_invalidate_locked as the dominant nativeCPU site. No production edits or device actions by this reviewer.

No blocking correctness issue found in the reviewed diff. The fixed256-bucketPC lookup remains the canonical owning index. A second65536-bucket page index points to the same entries. Both are inserted/removed under mm->lock. A pointer-to-link backlink enables constant-time unlink from the PC chain; insertion repairs the formerhead's backlink, and deletion repairs the successor before reusing the removed entry's next pointer for ss_jetsam. Uncached single-use entries retain the old retirement path and are never indexed.

The invalidator visits min(range_length,page_hash_size) cyclic page buckets. For a small range these are exactly its candidatebuckets; for a large/all range it visits everybucket once. Exact PAGE(pc) checks preserve entries whose distinct pages collide modulo65536. Nodes retain the existing deferred-reclamation lifetime. Teardown frees entries once through the PC chain/jetsam and frees the extra page array separately; constructor allocation-failure cleanup covers the extra array.

SS-only invalidation now contributes to did and increments generation, so an in-flight translation cannot be cached across an observed SS invalidation. Mapping/protection/CoW writers are serialized against execution/translation by mem->lock: task.c holds its read lock across cpu_run_to_interrupt. The existing coarse bloomfilter remains conservative; this patch reduces the cost of falsepositives rather than making it authoritative. LegalARM64 instructions are4-bytealigned and gen_step reads one instruction. The existing PAGE(pc) predicate is retained; misaligned illegalPC handling is outside this change.

Memory increase is512KiB per JITaddressspace for65536pointers, plus16bytes perSSentry for two pointers. Regression requirements sent to the owner: multiplePCs ononepage, PC-chain middle/head removals, collidingpages including highaddresses, exclusive rangeend, fullrange, cached versus one-shot lifecycle, reinsertion/backlink validity, generation, and allocation cleanup. Tests and physical performance validation are owned separately; passing this source review alone does not establish a game-speed result.
