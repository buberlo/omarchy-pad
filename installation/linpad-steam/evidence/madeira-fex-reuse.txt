Reusable Madeira findings
- Its iOS host handles executable memory through a dedicated shared RX/RW
  allocation pool, with 16 KiB host pages and explicit cache coherency checks.
  LinPad's Linux FEX currently executes through LinPad's ARM64 emulator; its
  JIT allocation path is different. Copying Madeira's native pool hooks into
  the Linux FEX executable would not produce the same integration.
- Madeira publishes actual Apple CPU feature availability to its Windows
  FEX modules using FEX_MADEIRA_HOSTPROBE. That parser is in its Windows
  CPUFeatures.cpp; the variable is not a generic Linux FEX fix. No speculative
  CPU feature override was added to the Linux runtime.
- Madeira Dock authenticates and launches through Valve's Windows client
  libraries while deliberately avoiding Chromium. It depends on Wine and
  pinned Windows client interfaces; it is not a drop-in Linux Steam UI.
- Madeira's standalone native FEXBridge Linux syscall handler supports only
  stdout/stderr writes and exit for small probes. It does not replace the
  Linux syscall environment Steam needs.

Applied here
- Both Apple memory capabilities were explicitly approved by the user,
  provisioned, signed, installed and tested on the iPad.
- LinPad now supports MIDR_EL1 reads and eventfd semaphore mode, handles
  relative access through non-directory descriptors, accepts a null signal
  mask in pselect6, and preserves EPOLLONESHOT registrations for MOD rearming.
- A proc-file allocation failure now returns ENOMEM instead of dereferencing
  a null pointer, matching the native crash report observed during testing.
- Vulkan cube rendering still works in the rebuilt app.
